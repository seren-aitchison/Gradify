Free Computer Science course: revision notes, flashcards and questions

TechGradify's free Computer Science course runs from Computational Thinking and Problem Solving to Security, AI and Society: 179 lessons in 12 schools, each with notes, flashcards and check questions at three levels (Foundation, Application, Evaluation). It's written for developers, data scientists and AI engineers.

Study material, not a qualification or legal advice. TechGradify teaches computer science for GCSE, A level and the first year of university, but it isn't an exam board resource or an accredited course: check the details of your own specification with your teacher or exam board. The lessons were drafted with AI assistance and haven't yet been reviewed by subject experts, so they may contain errors. Security lessons explain attacks so that you can defend against them: trying them on systems you don't own or have permission to test can be a criminal offence under the Computer Misuse Act 1990. The law lessons describe UK law for study; for a real data protection question, see the ICO or a qualified adviser.

Schools and lessons

School 1: Computational Thinking and Problem Solving

14 lessons

Computational Thinking and Problem Solving: key terms, sample flashcards and a quick quiz

  1. What is computer science?: Computer science is the study of computation: what can be computed, how to compute it efficiently and how to build reliable systems that do it.
  2. Abstraction: Abstraction means removing detail that doesn't matter for a problem so that you can focus on what does.
  3. Decomposition: Decomposition means breaking a complex problem into smaller sub-problems that can each be understood, solved and tested separately.
  4. Algorithmic thinking: Algorithmic thinking is the ability to define a precise, ordered set of steps that solves a problem for every valid input.
  5. Pattern recognition and generalisation: Pattern recognition means spotting similarities between problems or within a problem, so that a solution can be reused.
  6. Thinking ahead and thinking procedurally: Thinking ahead means identifying a solution's inputs, outputs and preconditions before building it, and planning for reuse.
  7. Pseudocode: Pseudocode is a structured, language-independent way of writing an algorithm.
  8. Flowcharts: A flowchart shows an algorithm as a diagram of standard symbols joined by arrows.
  9. Trace tables: A trace table records the value of each variable as an algorithm runs, line by line.
  10. Boolean logic: Boolean logic works with values that are either True or False and combines them with the operators AND, OR and NOT.
  11. Logic gates and truth tables: Logic gates are electronic circuits that carry out Boolean operations on binary signals.
  12. Simplifying Boolean expressions: Boolean algebra lets you simplify logic expressions so that circuits need fewer gates and conditions are easier to read.
  13. Thinking concurrently: Thinking concurrently means identifying parts of a problem that can happen at the same time.
  14. The limits of computation: Some problems can't be solved by any algorithm, and others can be solved in principle but would take impossibly long.

School 2: Python Programming Fundamentals

15 lessons

Python Programming Fundamentals: key terms, sample flashcards and a quick quiz

  1. Programs and the Python interpreter: A program is a sequence of instructions a computer carries out.
  2. Variables and assignment: A variable is a named location that holds a value which can change while a program runs.
  3. Data types and casting: Every value in Python has a data type that decides what it can do.
  4. Input and output: Programs communicate through input and output.
  5. Arithmetic operators: Python's arithmetic operators do the calculations at the heart of most programs.
  6. Comparison and logical operators: Comparison operators compare two values and produce True or False; logical operators combine those results.
  7. Selection with if, elif and else: Selection lets a program choose which code to run depending on a condition.
  8. Definite iteration: for loops: Definite (count-controlled) iteration repeats code a known number of times.
  9. Indefinite iteration: while loops: Indefinite (condition-controlled) iteration repeats code for as long as a condition stays True, when the number of repetitions isn't known in advance.
  10. Nested selection and iteration: Control structures can be placed inside one another: an if inside a loop, a loop inside a loop, or an if inside an if.
  11. Strings: indexing, slicing and methods: A string is a sequence of characters.
  12. Defining and calling functions: A function is a named block of code that performs one task and can be called whenever it is needed.
  13. Parameters, arguments and return values: Parameters let a function work on different data each time it is called, and return values pass results back.
  14. Scope: local and global variables: Scope is the part of a program in which a name can be used.
  15. Using modules: random and math: A module is a file of reusable code, such as functions and constants, that a program can import.

School 3: Data Structures, Files and Robust Code in Python

17 lessons

Data Structures, Files and Robust Code in Python: key terms, sample flashcards and a quick quiz

  1. Lists: A list is an ordered, changeable collection of items held under one name.
  2. List operations and methods: Python lists come with methods for adding, removing, searching and sorting items.
  3. Two-dimensional lists: A two-dimensional list is a list of lists, used to store a table or grid such as a game board, a seating plan or a spreadsheet.
  4. Tuples: A tuple is an ordered, immutable collection: once created, its items can't be changed.
  5. Dictionaries: A dictionary stores key-value pairs, so that a value can be found quickly from its key rather than its position.
  6. Sets: A set is an unordered collection of unique items.
  7. Choosing a Python data structure: Python's built-in list, tuple, dictionary and set each suit different jobs.
  8. Reading text files: Programs store data permanently in files so that it survives after they end.
  9. Writing and appending to files: Programs save results by writing to files.
  10. CSV files: A CSV (comma-separated values) file stores a table as text, one record per line with fields separated by commas.
  11. Input validation and defensive design: Defensive design means anticipating how a program might be misused or given bad data, and building it to cope.
  12. Exception handling with try and except: An exception is an error detected while a program runs.
  13. Types of error: syntax, runtime and logic: Programs go wrong in three different ways: syntax errors break the rules of the language, runtime errors stop a running program, and logic errors give the wrong result.
  14. Testing: normal, boundary and erroneous data: Testing runs a program with chosen data to check that it behaves as intended.
  15. Unit testing and test plans: Unit testing checks the smallest parts of a program, usually functions, automatically and repeatably.
  16. Debugging strategies: Debugging is the process of finding and fixing the cause of an error.
  17. Code quality and maintainability: Maintainable code is easy for other people (and your future self) to read, change and fix.

School 4: Algorithms

19 lessons

Algorithms: key terms, sample flashcards and a quick quiz

  1. Linear search: Linear search checks each item of a list in turn until it finds the target or reaches the end.
  2. Binary search: Binary search finds an item in a sorted list by repeatedly checking the middle item and discarding the half that can't contain the target.
  3. Bubble sort: Bubble sort repeatedly passes through a list, swapping adjacent items that are in the wrong order, until no swaps are needed.
  4. Insertion sort: Insertion sort builds a sorted section at the start of the list, taking each next item and inserting it into its correct place among the items already sorted.
  5. Merge sort: Merge sort splits a list in half repeatedly until each part has one item, then merges the parts back together in order.
  6. Quicksort: Quicksort picks a pivot, partitions the list into items smaller and larger than the pivot, then sorts each part recursively.
  7. Measuring efficiency: Algorithms are compared by how their use of time and memory grows as the input grows, not by timing them on one computer.
  8. Big O notation: Big O notation describes the upper bound on how an algorithm's time or space grows with input size, ignoring constants and lower-order terms.
  9. Comparing algorithm complexity: Knowing the Big O of algorithms lets you predict how they scale and choose between them.
  10. Time and space trade-offs: Faster algorithms often need more memory, and memory-saving algorithms often take longer.
  11. Recursion: A recursive function is one that calls itself on a smaller version of the same problem.
  12. Recursive and iterative solutions: Many problems can be solved either recursively or with loops.
  13. Breadth-first and depth-first traversal: Graph traversal visits every reachable vertex of a graph in a systematic order.
  14. Dijkstra's shortest path algorithm: Dijkstra's algorithm finds the shortest path from one vertex to every other vertex in a weighted graph with non-negative edge weights.
  15. A* search: A* search finds a shortest path from a start to a single goal, using a heuristic estimate of the remaining distance to explore the most promising vertices first.
  16. Divide and conquer: Divide and conquer solves a problem by splitting it into smaller independent sub-problems of the same type, solving them (often recursively) and combining their solutions.
  17. Greedy algorithms: A greedy algorithm builds a solution step by step, always taking the choice that looks best right now.
  18. Dynamic programming: Dynamic programming solves problems with overlapping sub-problems by solving each sub-problem once and storing the result.
  19. Backtracking: Backtracking builds a solution one choice at a time, and as soon as a partial solution can't lead to a valid answer it undoes the last choice and tries another.

School 5: Data Structures

15 lessons

Data Structures: key terms, sample flashcards and a quick quiz

  1. Abstract data types: An abstract data type (ADT) defines a collection of data by the operations it supports, not by how it is stored.
  2. Arrays and records: An array stores a fixed number of items of the same type in consecutive memory, so any item can be reached directly by its index.
  3. Stacks: A stack is a last-in, first-out (LIFO) collection: items are added and removed only at the top.
  4. Queues: A queue is a first-in, first-out (FIFO) collection: items join at the rear and leave from the front.
  5. Circular and priority queues: A circular queue reuses array space by wrapping its pointers round to the start; a priority queue removes the highest-priority item first.
  6. Linked lists: A linked list stores items in nodes, each holding data and a pointer to the next node.
  7. Trees: A tree is a hierarchical data structure of nodes connected by edges, with one root and no cycles.
  8. Binary search trees: A binary search tree (BST) keeps its items ordered: everything in a node's left subtree is smaller and everything in its right subtree is larger.
  9. Tree traversal: Traversing a tree means visiting every node exactly once.
  10. Graphs: A graph is a set of vertices joined by edges.
  11. Adjacency matrices and adjacency lists: Graphs are stored in programs as adjacency matrices or adjacency lists.
  12. Hash tables: A hash table stores key-value pairs in an array, using a hash function to turn each key into an array index.
  13. Collision resolution: A collision happens when two keys hash to the same slot.
  14. Static and dynamic data structures: A static data structure has a fixed size set when it is created; a dynamic one grows and shrinks while the program runs.
  15. Comparing data structures: Choosing the right data structure is often what makes a program fast.

School 6: Data Representation

16 lessons

Data Representation: key terms, sample flashcards and a quick quiz

  1. Binary and denary: Computers store all data as binary: patterns of 0s and 1s.
  2. Hexadecimal: Hexadecimal (base 16) is a compact way for people to read and write binary: each hex digit stands for exactly four bits.
  3. Binary arithmetic and overflow: Computers add numbers in binary using the same column method as denary, carrying a 1 whenever a column totals 2 or more.
  4. Binary shifts: A binary shift moves every bit of a number left or right.
  5. Two's complement: Two's complement is the standard way computers store negative whole numbers.
  6. Fixed-point and floating-point numbers: Real numbers with fractional parts are stored in binary either in fixed point, with the binary point in a set position, or in floating point, as a mantissa and an exponent.
  7. Units of data: Data sizes are measured in bits and bytes and in larger units such as kilobytes, megabytes and gigabytes.
  8. Character sets: ASCII and Unicode: Text is stored by giving every character a number, its code, defined by a character set.
  9. Bitmap images: A bitmap image is a grid of pixels, each stored as a binary colour code.
  10. Vector graphics: Vector graphics store an image as a list of shapes and their properties rather than as pixels.
  11. Sound: Sound is an analogue wave, so it must be sampled to be stored digitally.
  12. Lossy and lossless compression: Compression reduces the size of a file so it takes less storage and transfers faster.
  13. Run-length encoding: Run-length encoding (RLE) is a simple lossless compression method that replaces runs of repeated values with a count and the value.
  14. Huffman coding: Huffman coding is a lossless compression method that gives short binary codes to frequent characters and longer codes to rare ones.
  15. Ciphers: Caesar and Vernam: Encryption turns plaintext into ciphertext that only someone with the key can read.
  16. Error detection: parity and check digits: Data can be corrupted when it is transmitted or typed in.
