Five sample flashcards

What is research data management?

The planning and care of data throughout and after a research project. From “Research data management” →

In plain English: Research data management covers how data are organised, stored, documented, shared and preserved. Key idea: Research data management is the planning and care of data across the lifecycle, from planning and collection to storage, sharing, preservation and reuse, saving time, preventing loss and supporting integrity.

What is a README file?

A file explaining the contents and structure of a folder or project. From “File organisation and version control” →

In plain English: Clear file organisation and version control prevent confusion and lost work. Key idea: Use a consistent folder structure, keep raw data unchanged, name files with ISO dates and versions, avoid spaces and document conventions in a README; use Git or version histories for tracking changes.

What is a codebook?

Documentation describing the variables and codes in a dataset. From “Archiving and data sharing” →

In plain English: Sharing and archiving data allows others to verify, reuse and build on research. Key idea: Sharing supports verification and reuse, following "as open as possible, as closed as necessary"; prepare data in open formats with documentation, consent and licences, and deposit in suitable repositories with open, safeguarded or controlled access.

What is in-principle acceptance?

A journal's commitment to publish if the approved protocol is followed. From “Preregistration and registered reports” →

In plain English: Preregistration and registered reports commit researchers to their plans before data are collected. Key idea: Preregistration records hypotheses and analysis plans before data collection; registered reports review methods before results and guarantee publication if followed, reducing p-hacking, HARKing and publication bias.

What is literate programming?

Combining code, output and narrative text in one document. From “Reproducible workflows” →

In plain English: A reproducible workflow lets you or others regenerate results from raw data. Key idea: Reproducible workflows keep raw data unchanged, use scripts for all processing, version control, environment management and automatic outputs, with tools such as R Markdown, Quarto, Jupyter, renv, conda and Docker.

Key takeaways

  • Research data management is the planning and care of data across the lifecycle, from planning and collection to storage, sharing, preservation and reuse, saving time, preventing loss and supporting integrity.
  • A data management plan describes data types, documentation, ethics and legal issues, storage and backup, sharing and preservation and responsibilities; it should be specific, match consent forms and be updated as the project develops.
  • Use a consistent folder structure, keep raw data unchanged, name files with ISO dates and versions, avoid spaces and document conventions in a README; use Git or version histories for tracking changes.
  • Store data on secure institutional systems, follow the 3-2-1 backup rule, encrypt devices, control access and report breaches promptly; avoid relying on personal devices or unapproved cloud services.
  • Pseudonymisation replaces identifiers with codes and remains personal data, while anonymisation removes identifiability; use aggregation, suppression, pseudonyms and generalisation, log changes and assess risk with the motivated intruder test.
  • Sharing supports verification and reuse, following "as open as possible, as closed as necessary"; prepare data in open formats with documentation, consent and licences, and deposit in suitable repositories with open, safeguarded or controlled access.

Common mistakes in Research Data Management and Open Research

  • Leaving data management until the end of a project. Decisions about formats, storage and documentation are much harder to fix later.
  • Writing a DMP that promises data sharing not covered in consent forms. Participants must know how their data will be used.
  • Editing raw data files directly. Always keep an unchanged copy of raw data and work on copies.
  • Using personal cloud accounts for participant data. These may not meet data protection or institutional requirements.
  • Assuming removing names makes data anonymous. Indirect identifiers can still identify people.
  • Promising open sharing of data that participants did not consent to share. Consent must cover sharing.

A Digital Curation Centre tool for writing data management plans.

Why should dates be written as YYYY-MM-DD in file names?

So files sort correctly in date order.

What is the 3-2-1 backup rule?

Three copies, on two types of media, with one off-site.

Are pseudonymised data personal data?

Yes, because a key allows re-identification.
