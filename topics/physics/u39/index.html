Five sample flashcards

Answer each from memory, then open it to check. Still foggy? Each card has the plain-English version.

What is machine epsilon in double precision?

About 2.2 × 10-16. From “Scientific programming” →

In plain English: Scientific programming turns physical models into code that computes answers no pen-and-paper method can reach. Key idea: Correct, tested and clearly written code matters more than clever tricks; respect floating-point limits.

What is the method of lines?

Discretising space only to obtain a system of ODEs, which are then integrated in time. From “Solving partial differential equations” →

In plain English: Partial differential equations govern fields in space and time: heat, waves, fluids, electromagnetism and quantum mechanics. Key idea: Know your PDE type: it dictates boundary conditions, stability limits and suitable methods.

Why use softening in N-body codes?

To avoid singular forces and tiny time steps in close encounters. From “N-body simulations” →

In plain English: N-body simulations follow many particles interacting through long-range forces, mainly gravity. Key idea: N-body codes use trees, meshes and multipoles to tame O(N2) gravity for millions to trillions of particles.

What is inverse transform sampling?

Applying the inverse cumulative distribution function to uniform random numbers. From “Random number generation” →

In plain English: Simulations need vast numbers of random-looking numbers. Key idea: Use modern, tested generators with recorded seeds; transform uniforms into whatever distribution you need.

What does a reduced χ2 much greater than 1 suggest?

The model is inadequate or the uncertainties are underestimated. From “Data analysis and fitting” →

In plain English: Data analysis extracts physical meaning from measurements and simulations: estimating parameters, testing hypotheses and quantifying uncertainty. Key idea: Fit with appropriate statistics, check residuals and reduced χ2, and report uncertainties honestly.

Key takeaways

  • Correct, tested and clearly written code matters more than clever tricks; respect floating-point limits.
  • Higher-order rules converge faster for smooth functions; Monte Carlo wins in high dimensions.
  • Central differences are second-order accurate; choose h to balance truncation and round-off.
  • Bracketing methods are safe, Newton is fast; robust solvers use both.
  • Choose RK45 for smooth problems, implicit methods for stiff ones, and symplectic integrators for long Hamiltonian runs.
  • Know your PDE type: it dictates boundary conditions, stability limits and suitable methods.

Common mistakes in Computational Physics

  • Never test floating-point equality with ==; use a tolerance such as abs(a − b) < 1e-12 × scale.
  • High-order rules can perform worse on non-smooth or noisy integrands; check convergence by refining h.
  • Making h ever smaller does not keep improving accuracy; below the optimum, round-off error explodes.
  • Newton's method needs a good initial guess; plot the function first.
  • A stable-looking result does not mean an accurate one; always check convergence by changing the step size.
  • Unphysical boundary reflections and too-coarse grids are the most common sources of PDE simulation error.

Lessons in this unit

  1. Scientific programming
    Scientific programming turns physical models into code that computes answers no pen-and-paper method can reach.
  2. Numerical integration
    Numerical integration (quadrature) approximates definite integrals by weighted sums of function values.
  3. Numerical differentiation
    Numerical differentiation estimates derivatives from function values at nearby points.
  4. Root-finding algorithms
    Root-finding algorithms solve f(x) = 0 when no formula exists.
  5. Solving ordinary differential equations
    Most physical ODEs, such as orbits, circuits and reaction kinetics, must be solved numerically.
  6. Solving partial differential equations
    Partial differential equations govern fields in space and time: heat, waves, fluids, electromagnetism and quantum mechanics.
  7. Finite difference methods
    Finite difference methods replace derivatives with differences on a regular grid, turning PDEs into algebraic equations.
  8. Finite element methods
    The finite element method breaks a complicated region into small elements, approximates the solution on each with simple functions, and assembles a global system.
  9. Finite volume methods
    Finite volume methods divide space into cells and track the flux of conserved quantities across cell faces.
  10. Monte Carlo simulation
    Monte Carlo methods use random sampling to estimate integrals, simulate stochastic processes and explore huge state spaces.
  11. Molecular dynamics
    Molecular dynamics simulates the motion of atoms and molecules by integrating Newton's equations with forces from interatomic potentials.
  12. N-body simulations
    N-body simulations follow many particles interacting through long-range forces, mainly gravity.
  13. Computational fluid dynamics
    Computational fluid dynamics (CFD) solves the equations of fluid flow numerically, predicting forces, heat transfer and mixing.
  14. Numerical linear algebra
    Numerical linear algebra solves systems of equations, least-squares problems and matrix factorisations, the core of almost every simulation.
  15. Eigenvalue algorithms
    Eigenvalue problems give normal modes, energy levels, stability and principal components.
  16. Fourier transforms and spectral methods
    Fourier transforms decompose signals and fields into frequencies, and the fast Fourier transform computes them in N log N operations.
  17. Optimisation and parameter estimation
    Optimisation finds the best parameters for a model or design by minimising a cost function.
  18. Random number generation
    Simulations need vast numbers of random-looking numbers.
  19. Error and stability analysis
    Every numerical result carries errors from modelling, discretisation, iteration and round-off.
  20. Parallel computing
    Parallel computing splits a problem across many processors that work simultaneously.
  21. High-performance computing
    High-performance computing (HPC) uses supercomputers with hundreds of thousands of processors and accelerators to tackle the largest scientific problems: climate projections, fusion plasmas, cosmology
  22. GPU computing
    Graphics processing units contain thousands of simple cores that run the same instructions on many data at once.
  23. Scientific visualisation
    Scientific visualisation turns numbers into images that reveal structure, trends and errors.
  24. Data analysis and fitting
    Data analysis extracts physical meaning from measurements and simulations: estimating parameters, testing hypotheses and quantifying uncertainty.
  25. Reproducible computational experiments
    A computational result is reproducible if others (or you, later) can rerun the code and get the same answer.
  26. Verification and validation of simulations
    Verification asks whether a code solves its equations correctly; validation asks whether those equations describe reality well enough.
  27. Machine learning in physics
    Machine learning finds patterns in data and builds fast models from examples.
  28. Physics-informed neural networks
    Physics-informed neural networks (PINNs) train a neural network to satisfy both data and the governing equations, by putting the PDE residual into the loss function.
  29. Digital twins and surrogate models
    A surrogate model is a fast approximation of an expensive simulation; a digital twin is a living virtual model of a real system, continuously updated with sensor data.

Computational Physics: questions students ask

What is catastrophic cancellation?

Loss of significant digits when subtracting nearly equal numbers.

Why use Monte Carlo for high-dimensional integrals?

Its error ∝ 1/√N doesn't depend on dimension.

What is automatic differentiation?

Exact evaluation of derivatives by applying the chain rule to each operation in code.

What is the convergence order of Newton's method?

Quadratic, near a simple root.
