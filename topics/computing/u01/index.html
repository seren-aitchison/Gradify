Five sample flashcards

Answer each from memory, then open it to check. Still foggy? Each card has the plain-English version.

What is an algorithm?

A finite, precise sequence of steps that solves a problem or carries out a task. From “What is computer science?” →

In plain English: Computer science is the study of computation: what can be computed, how to compute it efficiently and how to build reliable systems that do it. Key idea: Computer science is about methods and their properties (correctness, efficiency, limits), not about a particular machine or program; programming is how its ideas are expressed and tested.

What does a structure diagram show?

How a problem is decomposed: the whole problem at the top and its sub-problems as boxes beneath it. From “Decomposition” →

In plain English: Decomposition means breaking a complex problem into smaller sub-problems that can each be understood, solved and tested separately. Key idea: Decompose until each part does one clear job: small parts are easier to write, test, reuse and share among a team.

What is one drawback of caching?

It uses extra memory and can return stale data if the original changes. From “Thinking ahead and thinking procedurally” →

In plain English: Thinking ahead means identifying a solution's inputs, outputs and preconditions before building it, and planning for reuse. Key idea: State inputs, outputs and preconditions first: they define what the component promises and what its caller must provide.

What is a trace table used for?

Recording variable values step by step during a dry run, to see what an algorithm does and find logic errors. From “Trace tables” →

In plain English: A trace table records the value of each variable as an algorithm runs, line by line. Key idea: Trace exactly what the code says, one line at a time, recording every change: the computer doesn't know what you meant.

State De Morgan's first law.

NOT (A AND B) = NOT A OR NOT B. From “Simplifying Boolean expressions” →

In plain English: Boolean algebra lets you simplify logic expressions so that circuits need fewer gates and conditions are easier to read. Key idea: De Morgan's laws: break the bar, change the sign. NOT over an AND becomes an OR of NOTs, and vice versa.

Quick quiz: test yourself on Computational Thinking and Problem Solving

9 questions from the course, from foundation recall to stretch. Pick an answer, then say whether you knew it or guessed.

  1. Which best describes computer science? (Foundation recall)
    Show the answer

    The study of computation, algorithms and the systems that carry them out. Computer science is about computation itself: what can be computed and how. Using software is digital literacy; managing systems is IT; repair is a technical trade.

  2. What does abstraction involve? (Foundation recall)
    Show the answer

    Removing details that aren't needed to solve the problem. Abstraction removes unnecessary detail. Splitting a problem up is decomposition; repetition is iteration.

  3. Which describes decomposition? (Foundation recall)
    Show the answer

    Breaking a problem into smaller sub-problems. Decomposition breaks a problem down. Removing detail is abstraction; finding similarities is pattern recognition.

  4. A researcher proves that a new method finds routes on any map in half the steps of the old one. Which area of computer science is this mainly part of? (Exam style)
    Show the answer

    Algorithms and their analysis. The result concerns the number of steps a method takes, which is the analysis of algorithms. Networks and operating systems are systems areas; HCI studies how people use computers.

  5. A program simulates queues at a supermarket checkout. Which detail is best removed by abstraction? (Exam style)
    Show the answer

    The colour of each customer's coat. Arrival times, item counts and open tills all affect queue lengths; coat colour does not, so it can be removed.

  6. A team is building an online shop. Which is the best first-level decomposition? (Exam style)
    Show the answer

    Product catalogue, basket, payment, user accounts. Each sub-problem should be a distinct job of the system. Splitting by time of day, by language or by difficulty doesn't produce parts with a clear single purpose.

  7. Which is the strongest reply to the claim that computer science is "just programming"? (Stretch)
    Show the answer

    Programming expresses ideas, but the subject also asks which methods are correct, efficient and possible at all. Programming is central but is the medium, not the whole: analysing correctness, efficiency and computability is what makes it a science. The other options are false or overstate the case.

  8. A flood-risk model of a town keeps the streets and buildings but treats the ground as flat. What is the main risk of this abstraction? (Stretch)
    Show the answer

    It removes a detail that matters, so its predictions of where water flows may be wrong. Height decides where water flows, so removing it removes a relevant detail: the model becomes easier but wrong. An abstraction must keep every feature that affects the answer.

  9. A program is decomposed into two huge functions, each doing many unrelated tasks. What is the main weakness? (Stretch)
    Show the answer

    Each part has several jobs, so it is hard to test, reuse or share. Good decomposition gives each part one clear purpose; two large multi-purpose functions lose most of the benefits of testing, reuse and teamwork.

Key takeaways

  • Computer science is about methods and their properties (correctness, efficiency, limits), not about a particular machine or program; programming is how its ideas are expressed and tested.
  • A good abstraction keeps exactly the details needed for the purpose: too few and the model gives wrong answers, too many and it becomes hard to build and use.
  • Decompose until each part does one clear job: small parts are easier to write, test, reuse and share among a team.
  • An algorithm must be unambiguous, finite and correct for every valid input, not just the example you tried.
  • Find what stays the same and what changes: what stays the same becomes the body of a loop or function; what changes becomes a loop variable or a parameter.
  • State inputs, outputs and preconditions first: they define what the component promises and what its caller must provide.

Common mistakes in Computational Thinking and Problem Solving

  • Treating computer science as "learning to use software" or "learning a language". Languages change every decade; algorithms, data structures and the principles of systems last.
  • Thinking abstraction means "make it vague". An abstraction must be precise about what it keeps; it only removes what doesn't affect the answer.
  • Decomposing by when things happen ("first half of the program, second half") rather than by what each part does. Good parts have a single purpose and few connections to other parts.
  • Testing an algorithm on one typical example and assuming it is correct. Try edge cases: the first item being largest, all items equal, negative numbers, an empty input.
  • Copying and pasting a block of code and changing one value each time. If the same lines appear three times, generalise them.
  • Treating caching as free. A cache uses memory and can serve stale data if the original changes, so it must be invalidated or refreshed.

Lessons in this school

  1. What is computer science?
    Computer science is the study of computation: what can be computed, how to compute it efficiently and how to build reliable systems that do it.
  2. Abstraction
    Abstraction means removing detail that doesn't matter for a problem so that you can focus on what does.
  3. Decomposition
    Decomposition means breaking a complex problem into smaller sub-problems that can each be understood, solved and tested separately.
  4. Algorithmic thinking
    Algorithmic thinking is the ability to define a precise, ordered set of steps that solves a problem for every valid input.
  5. Pattern recognition and generalisation
    Pattern recognition means spotting similarities between problems or within a problem, so that a solution can be reused.
  6. Thinking ahead and thinking procedurally
    Thinking ahead means identifying a solution's inputs, outputs and preconditions before building it, and planning for reuse.
  7. Pseudocode
    Pseudocode is a structured, language-independent way of writing an algorithm.
  8. Flowcharts
    A flowchart shows an algorithm as a diagram of standard symbols joined by arrows.
  9. Trace tables
    A trace table records the value of each variable as an algorithm runs, line by line.
  10. Boolean logic
    Boolean logic works with values that are either True or False and combines them with the operators AND, OR and NOT.
  11. Logic gates and truth tables
    Logic gates are electronic circuits that carry out Boolean operations on binary signals.
  12. Simplifying Boolean expressions
    Boolean algebra lets you simplify logic expressions so that circuits need fewer gates and conditions are easier to read.
  13. Thinking concurrently
    Thinking concurrently means identifying parts of a problem that can happen at the same time.
  14. The limits of computation
    Some problems can't be solved by any algorithm, and others can be solved in principle but would take impossibly long.

Computational Thinking and Problem Solving: questions students ask

What is abstraction?

Removing unnecessary detail from a problem so that only the features relevant to solving it remain.

What is decomposition?

Breaking a complex problem into smaller sub-problems that can each be solved separately.

What two properties must every algorithm have besides being correct?

It must terminate after a finite number of steps, and each step must be unambiguous.

What is generalisation?

Replacing specific cases with a single solution, such as a loop or function with parameters, that works for a whole class of problems.
