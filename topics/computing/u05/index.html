Key terms and formulas at a glance

Abstract data type
A model of data defined by its operations and their behaviour, independent of implementation
Array
A fixed-size collection of elements of the same type stored in contiguous memory and accessed by index
Stack
A last-in, first-out collection where items are added and removed only at the top
Queue
A first-in, first-out collection: items join at the rear and leave from the front
Circular queue
A queue in a fixed array whose front and rear pointers wrap round to the start, reusing space
Linked list
A dynamic data structure of nodes, each holding data and a pointer to the next node
Tree
A connected, undirected graph with no cycles, usually with a designated root
Binary search tree
A binary tree in which every left subtree holds smaller values and every right subtree larger values than its node
Pre-order traversal
Visiting a node, then its left subtree, then its right subtree
Graph
A set of vertices connected by edges
Adjacency matrix
A 2D array recording whether (and with what weight) each pair of vertices is connected
Hash table
A data structure that stores key-value pairs in an array at positions computed by a hash function

Five sample flashcards

Answer each from memory, then open it to check. Still foggy? Each card has the plain-English version.

What is an abstract data type?

A model of data defined by the operations it supports and their behaviour, without saying how it is stored. From “Abstract data types” →

In plain English: An abstract data type (ADT) defines a collection of data by the operations it supports, not by how it is stored. Key idea: An ADT is a contract (operations and behaviour); a data structure is one way of fulfilling it. Code that uses only the contract survives a change of implementation.

What does FIFO mean?

First in, first out: items leave in the order they arrived. From “Queues” →

In plain English: A queue is a first-in, first-out (FIFO) collection: items join at the rear and leave from the front. Key idea: A queue removes items in arrival order; a linear array queue is simple but wastes the space at the front as items are dequeued.

What is a leaf node?

A node with no children. From “Trees” →

In plain English: A tree is a hierarchical data structure of nodes connected by edges, with one root and no cycles. Key idea: A tree has one root, every other node has one parent, and there are no cycles; a binary tree allows at most two children per node.

What is the degree of a vertex?

The number of edges connected to it. From “Graphs” →

In plain English: A graph is a set of vertices joined by edges. Key idea: Graphs model relationships: decide what the vertices and edges represent and whether edges need direction or weights, and many real problems become standard graph algorithms.

What is a collision in a hash table?

When two different keys hash to the same index. From “Collision resolution” →

In plain English: A collision happens when two keys hash to the same slot. Key idea: Linear probing stores colliding keys in the next free slots of the array; chaining stores them in a list at the same slot. Both keep average operations O(1) if the load factor is controlled.

Quick quiz: test yourself on Data Structures

9 questions from the course, from foundation recall to stretch. Pick an answer, then say whether you knew it or guessed.

  1. What does an abstract data type define? (Foundation recall)
    Show the answer

    The operations on the data and how they behave. An ADT is about behaviour; layout is the implementation's concern.

  2. Which describes an array as defined in exam specifications? (Foundation recall)
    Show the answer

    A fixed-size collection of elements of one type, accessed by index. Arrays are fixed in size, homogeneous and indexed.

  3. Which item does pop remove from a stack? (Foundation recall)
    Show the answer

    The most recently pushed item. A stack is last in, first out, so pop removes the top, most recent item.

  4. A team replaces the array inside its stack with a linked list. Code elsewhere that only calls push and pop is unchanged. Which principle does this show? (Exam style)
    Show the answer

    Separating an ADT's interface from its implementation. Because other code uses only the operations, the implementation can change freely.

  5. An array of 4-byte integers starts at address 1000. What is the address of element 5? (Exam style)
    Show the answer

    1020. Address = 1000 + 5 × 4 = 1020; elements are numbered from 0.

  6. Starting empty, a stack does push(A), push(B), push(C), pop(), push(D), pop(), pop(). Which item is left? (Exam style)
    Show the answer

    A. C is popped, D pushed then popped, then B popped, leaving only A.

  7. Why is it risky for code to read a stack's internal array directly instead of calling pop and peek? (Stretch)
    Show the answer

    The code breaks if the stack's implementation changes, and it may bypass rules such as last in, first out. Depending on internals ties code to one implementation and can violate the ADT's behaviour.

  8. A program stores each customer's name, phone number and balance. Which structure best represents all the customers? (Stretch)
    Show the answer

    An array of records, one record per customer. Records keep each customer's fields together; parallel arrays sorted separately would lose which values belong together.

  9. Which application needs a stack rather than a queue? (Stretch)
    Show the answer

    Checking that every opening bracket in an expression has a matching closing bracket. The most recent unclosed bracket must be matched first, which is last in, first out.

Key takeaways

  • An ADT is a contract (operations and behaviour); a data structure is one way of fulfilling it. Code that uses only the contract survives a change of implementation.
  • Arrays give constant-time access by index because elements are the same size and stored side by side; records group fields of different types describing one thing.
  • A stack adds and removes only at the top: the last item pushed is the first popped, and every operation takes constant time.
  • A queue removes items in arrival order; a linear array queue is simple but wastes the space at the front as items are dequeued.
  • A circular queue wraps its pointers with MOD so freed positions are reused; track a count, or leave one slot empty, to distinguish full from empty.
  • Linked lists insert and delete by changing pointers, without shifting items, but finding a position requires traversal from the head.

Common mistakes in Data Structures

  • Treating "stack" and "array" as the same kind of thing. A stack is an ADT; an array is one data structure that can implement it.
  • Assuming Python lists are arrays of values. A list holds references to objects anywhere in memory, which is why it can mix types and grow, at some cost in memory.
  • Forgetting to check for underflow before popping. Popping an empty stack must be handled, or the program reads invalid data or crashes.
  • Using list.pop(0) for a large queue in Python. Each dequeue shifts every remaining item; use collections.deque instead.
  • Testing front == rear alone to decide whether a circular queue is empty. With wrapping, the same condition can also mean full, unless a count or spare slot is used.
  • Changing pointers in the wrong order. Setting B's pointer to C before copying B's old next into C loses the rest of the list.

Lessons in this school

  1. Abstract data types
    An abstract data type (ADT) defines a collection of data by the operations it supports, not by how it is stored.
  2. Arrays and records
    An array stores a fixed number of items of the same type in consecutive memory, so any item can be reached directly by its index.
  3. Stacks
    A stack is a last-in, first-out (LIFO) collection: items are added and removed only at the top.
  4. Queues
    A queue is a first-in, first-out (FIFO) collection: items join at the rear and leave from the front.
  5. Circular and priority queues
    A circular queue reuses array space by wrapping its pointers round to the start; a priority queue removes the highest-priority item first.
  6. Linked lists
    A linked list stores items in nodes, each holding data and a pointer to the next node.
  7. Trees
    A tree is a hierarchical data structure of nodes connected by edges, with one root and no cycles.
  8. Binary search trees
    A binary search tree (BST) keeps its items ordered: everything in a node's left subtree is smaller and everything in its right subtree is larger.
  9. Tree traversal
    Traversing a tree means visiting every node exactly once.
  10. Graphs
    A graph is a set of vertices joined by edges.
  11. Adjacency matrices and adjacency lists
    Graphs are stored in programs as adjacency matrices or adjacency lists.
  12. Hash tables
    A hash table stores key-value pairs in an array, using a hash function to turn each key into an array index.
  13. Collision resolution
    A collision happens when two keys hash to the same slot.
  14. Static and dynamic data structures
    A static data structure has a fixed size set when it is created; a dynamic one grows and shrinks while the program runs.
  15. Comparing data structures
    Choosing the right data structure is often what makes a program fast.

Data Structures: questions students ask

Why is accessing an array element by index O(1)?

Its address is computed directly as the base address plus index times element size.

What does LIFO mean?

Last in, first out: the most recently added item is removed first.

How does a circular queue advance its rear pointer?

rear = (rear + 1) MOD size, wrapping to 0 after the last position.

What does each node in a singly linked list contain?

A data item and a pointer to the next node.
