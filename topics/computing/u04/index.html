Key terms and formulas at a glance

Linear search
A search that checks each item in turn until the target is found or the list ends
Binary search
A search of a sorted list that compares the middle item and discards half the remaining items each step
Bubble sort
A sort that repeatedly swaps adjacent out-of-order items until a pass makes no swaps
Insertion sort
A sort that inserts each item in turn into its correct place within a growing sorted section
Merge sort
A divide-and-conquer sort that splits a list into halves, sorts them and merges the sorted halves
Quicksort
A divide-and-conquer sort that partitions a list around a pivot and sorts each part recursively
Time complexity
How the number of operations an algorithm performs grows with the size of its input
Big O notation
A notation giving an upper bound on how an algorithm's time or space grows with input size
Scalability
How well an algorithm copes as its input grows
Time-space trade-off
Using more memory to reduce running time, or more time to reduce memory use
Recursion
A technique in which a function calls itself to solve a smaller instance of the same problem
Iteration
Repeating steps using a loop

Five sample flashcards

Answer each from memory, then open it to check. Still foggy? Each card has the plain-English version.

Does linear search need the list to be sorted?

No: it checks every item in turn, so it works on unsorted lists. From “Linear search” →

In plain English: Linear search checks each item of a list in turn until it finds the target or reaches the end. Key idea: Linear search makes up to n comparisons for n items: on average about n/2 when the target is present, and all n when it is absent.

On what kind of data does insertion sort perform best?

Data that is already sorted or nearly sorted. From “Insertion sort” →

In plain English: Insertion sort builds a sorted section at the start of the list, taking each next item and inserting it into its correct place among the items already sorted. Key idea: Insertion sort keeps the front of the list sorted and inserts each new item into it; on nearly sorted data, each insertion needs very few shifts.

What is the time complexity of accessing a list item by its index?

O(1), constant time. From “Big O notation” →

In plain English: Big O notation describes the upper bound on how an algorithm's time or space grows with input size, ignoring constants and lower-order terms. Key idea: Sequential steps add (keep the largest); nested loops multiply; halving the problem each step gives a logarithm.

Why does recursion usually use more memory than iteration?

Each recursive call adds a stack frame, so memory grows with the depth of recursion. From “Recursive and iterative solutions” →

In plain English: Many problems can be solved either recursively or with loops. Key idea: Recursion is natural for self-similar problems such as trees and divide and conquer; iteration is usually more memory-efficient and faster for simple repetition.

What are the three steps of divide and conquer?

Divide the problem into sub-problems, conquer (solve) them, and combine their solutions. From “Divide and conquer” →

In plain English: Divide and conquer solves a problem by splitting it into smaller independent sub-problems of the same type, solving them (often recursively) and combining their solutions. Key idea: Halving a problem repeatedly gives log2 n levels; if each level costs O(n) the total is O(n log n), and if each level costs O(1), as in binary search, the total is O(log n).

Quick quiz: test yourself on Algorithms

9 questions from the course, from foundation recall to stretch. Pick an answer, then say whether you knew it or guessed.

  1. How does linear search find an item? (Foundation recall)
    Show the answer

    It checks each item in order until it finds the target or reaches the end. Linear search is a sequential check of every item. Halving is binary search; hashing is used by dictionaries.

  2. What does binary search compare the target with first? (Foundation recall)
    Show the answer

    The middle item of the list. It starts at the middle so that one comparison can rule out half the list.

  3. What does bubble sort compare? (Foundation recall)
    Show the answer

    Adjacent pairs of items. Bubble sort compares neighbours and swaps them if they are in the wrong order.

  4. How many comparisons does a linear search make to find 8 in [3, 9, 1, 8, 4]? (Exam style)
    Show the answer

    4. It compares 3, 9, 1 and then 8, which matches on the fourth comparison.

  5. Binary search on a sorted list of 15 items checks index 7 first. The target is smaller. Which indexes remain? (Exam style)
    Show the answer

    0 to 6. A smaller target must lie before the midpoint, so high becomes 6.

  6. What is [3, 1, 2] after the first pass of bubble sort into ascending order? (Exam style)
    Show the answer

    [1, 2, 3]. (3, 1) swap gives [1, 3, 2]; (3, 2) swap gives [1, 2, 3].

  7. A list of 50 unsorted items is searched only once. Why is linear search the better choice than sorting and then binary searching? (Stretch)
    Show the answer

    Sorting costs more than the single linear search it would replace. Sorting takes about n log n steps; one linear search takes at most n, so for a single search on unsorted data linear search wins.

  8. A company searches a 10-million-item list once a day, and the list changes completely every day. Which approach is likely fastest overall? (Stretch)
    Show the answer

    Linear search, because sorting every day costs more than one search. Binary search needs sorted data; sorting 10 million items takes far longer than one linear pass of 10 million comparisons.

  9. Why is bubble sort rarely used for large data sets? (Stretch)
    Show the answer

    Its comparisons grow with the square of n, so it becomes very slow. O(n2) time means doubling the data roughly quadruples the work; merge sort or Timsort are far faster.

Key takeaways

  • Linear search makes up to n comparisons for n items: on average about n/2 when the target is present, and all n when it is absent.
  • Binary search needs sorted data and makes at most about log2 n comparisons, so its time complexity is O(log n).
  • Each pass of bubble sort moves the largest unsorted item to its final place; stopping when a pass makes no swaps avoids wasted passes.
  • Insertion sort keeps the front of the list sorted and inserts each new item into it; on nearly sorted data, each insertion needs very few shifts.
  • Merge sort's time is O(n log n) in the best, average and worst case, but it needs extra memory for the merged lists.
  • Quicksort does its work while partitioning, before the recursive calls; merge sort does its work while merging, after them.

Common mistakes in Algorithms

  • Returning "not found" inside the loop on the first mismatch. The return -1 must come after the loop, once every item has been checked.
  • Forgetting to move low to mid + 1 (or high to mid − 1). Setting low = mid can loop forever when two items remain.
  • Stopping after one pass. One pass only guarantees the largest item is in place; keep passing until a pass makes no swaps.
  • Confusing insertion sort with bubble sort. Insertion sort moves one item into a growing sorted section; bubble sort swaps neighbours across the whole unsorted part.
  • Thinking the splitting stage sorts anything. All the ordering happens during the merges.
  • Picking the first item as pivot on data that is often already sorted. Every partition is lopsided and quicksort degrades to O(n2).

Lessons in this school

  1. Linear search
    Linear search checks each item of a list in turn until it finds the target or reaches the end.
  2. Binary search
    Binary search finds an item in a sorted list by repeatedly checking the middle item and discarding the half that can't contain the target.
  3. Bubble sort
    Bubble sort repeatedly passes through a list, swapping adjacent items that are in the wrong order, until no swaps are needed.
  4. Insertion sort
    Insertion sort builds a sorted section at the start of the list, taking each next item and inserting it into its correct place among the items already sorted.
  5. Merge sort
    Merge sort splits a list in half repeatedly until each part has one item, then merges the parts back together in order.
  6. Quicksort
    Quicksort picks a pivot, partitions the list into items smaller and larger than the pivot, then sorts each part recursively.
  7. Measuring efficiency
    Algorithms are compared by how their use of time and memory grows as the input grows, not by timing them on one computer.
  8. Big O notation
    Big O notation describes the upper bound on how an algorithm's time or space grows with input size, ignoring constants and lower-order terms.
  9. Comparing algorithm complexity
    Knowing the Big O of algorithms lets you predict how they scale and choose between them.
  10. Time and space trade-offs
    Faster algorithms often need more memory, and memory-saving algorithms often take longer.
  11. Recursion
    A recursive function is one that calls itself on a smaller version of the same problem.
  12. Recursive and iterative solutions
    Many problems can be solved either recursively or with loops.
  13. Breadth-first and depth-first traversal
    Graph traversal visits every reachable vertex of a graph in a systematic order.
  14. Dijkstra's shortest path algorithm
    Dijkstra's algorithm finds the shortest path from one vertex to every other vertex in a weighted graph with non-negative edge weights.
  15. A* search
    A* search finds a shortest path from a start to a single goal, using a heuristic estimate of the remaining distance to explore the most promising vertices first.
  16. Divide and conquer
    Divide and conquer solves a problem by splitting it into smaller independent sub-problems of the same type, solving them (often recursively) and combining their solutions.
  17. Greedy algorithms
    A greedy algorithm builds a solution step by step, always taking the choice that looks best right now.
  18. Dynamic programming
    Dynamic programming solves problems with overlapping sub-problems by solving each sub-problem once and storing the result.
  19. Backtracking
    Backtracking builds a solution one choice at a time, and as soon as a partial solution can't lead to a valid answer it undoes the last choice and tries another.

About 10, since 210 = 1,024.

What is guaranteed after the first pass of bubble sort?

The largest item is in its final position at the end of the list.

In insertion sort, what is true of the items before the current position?

They form a sorted section.

What is the time complexity of merge sort?

O(n log n) in the best, average and worst cases.
