# The education catalogue (MyGradify Stage 2 foundation)

The catalogue is Gradify's public reference data about education: systems, providers, offerings, structures, units,
assessments, curricula and rules, with provenance and verification on every field. It is **separate** from what
students enter (`profiles.learner.academic`, Stage 4) and from verified academic rules, which are the only thing allowed
to change a student's numbers. The architecture is in `docs/PROPOSAL-mygradify-catalogue.md` (Proposal 5 and
Addendum A); the sources are in `docs/STAGE1-RESEARCH-REPORT.md`.

**Status (Stage 2):**
- Repository only.
- No real data is ingested or published: `data/` is excluded from the site (`scripts/build-site.mjs`).
- Nothing in the app imports the reader yet.

## The rules the validator enforces

1. **IDs:**
   - Gradify-owned and permanent; the prefix matches the type.
   - Unique, and never reused: a tombstoned ID can't come back.
   - External numbers (UKPRN, URN, UNITID…) are **aliases**: unique while valid, and pointing only at live records.
2. **Rights are per source and per field:**
   - A field is accepted only from a source whose verdict is `cleared` (or `fixture`, inside a fixture bundle) and whose
     `fields_allowed[type]` lists that field.
   - Publishing needs `rights.publish`; ingesting without publishing is a separate right.
   - An evidence **extract** needs `rights.evidence`; otherwise evidence is `link_only` (a URL and hash, no text).
3. **Personal data** is refused in any field name matching named-person or contact patterns (head, headteacher,
   governor, contact, first/last name, email, phone…), whatever the source says. The OGL excludes personal data.
4. **Verification, per field:**
   - `verified` or `partially_verified` needs a review by an **owner-approved**, competent reviewer, with evidence from
     the same source.
   - High-importance rules, programme structures, assessment weights and `includes` edges need a **second, different**
     reviewer.
   - Automated processes can only produce `unverified` or `outdated`.
5. **Source changes:**
   - A field with a pending change must be `outdated` or `unverified`.
   - The build publishes its **last verified value**, never the unreviewed one, and only lists which fields changed.
6. **Relationships:**
   - Edges join live records of the right types (`part_of_system`, `offers`, `has_structure`, `includes`, `covers`,
     `assesses`, `aligned_to`, `governed_by`, `supersedes`).
   - A structure needs its `has_structure` edge.
   - Tombstones resolve without loops.

## The reader's guarantees (`kit/data/catalogue.js`)

- **Search** results are suggestions. Nothing links until the student explicitly confirms (`confirmLink(..., {
  confirmed: true })`). A typed name never inherits anything.
- **Status** is per field. `statusOf(record, fieldsShown)` is the lowest status of the fields shown, so a checked title
  never makes a programme look checked. `describeStatus` says it in words ("Title checked · Length not yet checked").
  A field past `next_review` or `effective_to`, or with a pending change, is `outdated`.
- **Calculations** get `calculationValues(record)`: verified values only. A pending change keeps the last verified
  value.
- **Rules** (`rulesFor(entry)`):
  - Nothing applies unless the entry is linked.
  - Even then, a rule applies only if the link (`governed_by` edge) is verified and every field of the rule is
    verified, with two reviewers when high importance, and no change is pending.
  - Everything else comes back as `info`, with the reason it isn't applied.
- **Missing data** never blocks. An unknown region, provider, offering or structure returns empty or `null`, never an
  error, so the student can carry on with "Not listed" or a handbook import.
- **Merged** IDs resolve to the survivor. **Split** IDs return `{ split: [...] }` for the student to choose.

## Published layout (written by `scripts/catalogue/build.mjs`)

```
manifest.json                         schema version, build id, sources with licence and attribution, counts, regions
systems.json
providers/<CC>/<REGION>/index.json    compact search rows: [id, name, alt names, kind, town, lifecycle]
objects/<type>/<bucket>.json          full public records (bucket = last two ID characters)
relations/<bucket>.json               edges touching each ID, both directions
tombstones.json
```

**Never published:** evidence, reviewer identities, aliases, or pending (unreviewed) values.

## Adding a source (Stage 3 and later, each needing approval)

1. Research it as in the Stage 1 report: read its own terms, and quote them.
2. Add `data/catalogue/sources/<name>.json` with `verdict`, separate `rights`, `fields_allowed` per record type, and
   `excluded_source_fields` and `conditions`.
3. Owner approval (G3) to change the verdict to `cleared`.
4. Write a build script that maps only the allowed fields and sets every field `unverified`.
