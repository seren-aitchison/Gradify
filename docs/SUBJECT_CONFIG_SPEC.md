# Subject configuration spec

Generated from `kit/course/spec.js` by `scripts/subject-spec-doc.mjs`; edit the spec there, not here.

A Gradify course is a config object handed to the shared course engine (`mountCourse(el, cfg)` in `kit/course/course.js`). `checkCourse(cfg)` checks a config against this spec and `tests/cross-site.test.mjs` runs it on every course. A subject adapter (`kit/subjects/`) can supply any of these fields as defaults, which the course's own fields override. See [GRADIFY_PLATFORM.md](GRADIFY_PLATFORM.md) for how the pieces fit.

## core

| Field | Type | Required | What it does |
|---|---|---|---|
| `site` | string | yes | The site's brand name ("MathGradify"). Progress and activity are logged under it. |
| `slug` | string | yes | Short id for the subject ("maths"): storage keys, the tutor's subject rules, attempt records. |
| `name` | string | yes | The subject's display name ("Mathematics"). |
| `page` | string |  | The course page's path ("/historygradify/course/"), set by scripts/new-course.mjs; registered in kit/learning/learner-data.js. |
| `app` | string |  | Link to the site's study app (flashcards, Notes Studio). |
| `theme` | object |  | { accent, spectrum }: the course's colours, overriding the site's. |
| `notice` | string |  | A short HTML notice shown above the course (scope, status, which exam boards). |
| `units` | array | yes | The syllabus: [{ id, n, title, lessons: [{ id, title, module? }] }]. Lesson ids are permanent (ids.js). |
| `unitWord` | string |  | What a unit is called ("School", "Unit"). Defaults to "Unit". |
| `trackWord` | string |  | What a track is called ("Stage"). Defaults to "Track". |
| `tracks` | array | yes | Groups of units shown on the Learn road: [{ name, from, to, units: [n…] }]. |
| `paths` | array | yes | Suggested routes through the course: [{ name, sub, units: [n…] }]. |
| `blurbs` | object |  | A one-line description per unit id. |
| `overview` | object |  | { headline, intro, sources, learn: [[title, text]…] }: the course's overview page. |
| `extras` | array |  | [[title, text, href]…]: links to the site's other tools. |
| `adapter` | string |  | The subject adapter the course was defined with ("maths", "science", "programming"). |

## review

| Field | Type | Required | What it does |
|---|---|---|---|
| `expert` | string |  | Who must sign a school off before it counts as published (scaffolded courses). |
| `qa` | object |  | Review record per unit (kit/courses/<slug>/qa.js): reviewed, sources, signoff. Never set by scripts. |
| `publish` | boolean |  | Publish units while review continues, each with its draft status shown. |
| `reviewLine` | boolean |  | Show a line under each lesson saying when it was written and its review status. |

## Checks beyond types

- Unit ids, lesson ids and slugs are unique; `slug` is lower case.
- `written`, `tracks` and `paths` name units that exist; `levels` has exactly three names.
- Every interactive has `id`, `title` and `load()`, and names only lessons that exist; every `evidence` entry names a real lesson.
- `workspace` has a `route` and `engine()`; `concepts` has a `modules` object (its references are checked by `npm run qa`).
- Any field not listed here is reported as unknown, so a typo can't silently switch something off.
