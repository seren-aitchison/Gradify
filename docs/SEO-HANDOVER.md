## How the system works (read before changing anything)

- Pages are generated: `node scripts/build-seo.mjs` then `node scripts/build-sitemap.mjs`. Never hand-edit files under the generated folders (`SEO_FOLDERS` in `scripts/seo/folders.mjs`).
- `page()` in `scripts/seo/shell.mjs` is the shell: hub header/footer, canonical, OG, breadcrumbs + BreadcrumbList, JSON-LD, share button, CTA.
- A tool page is static HTML with `<div class="tool" data-tool="<id>" data-mod="<module>" data-example='{"f":{…},"r":[…]}'>`. `assets/seo.js` imports `/assets/<data-mod>.js` and calls `mount(root)`, then adds the action bar.
- New top-level folders or root files must be added to `SEO_FOLDERS`/`SEO_FILES` **and** to `PUBLISH` in `scripts/build-site.mjs` (`tests/seo.test.mjs` checks both).
- Generated pages get module preload lists (`withPreloads` in build-seo). Any change to imports in `assets/seo.js` or modules it imports statically changes every generated page: regenerate.
- Modules under `assets/` that tests import must use **relative** imports (`./study-tools.js`), not `/assets/...`.
- CI (`.github/workflows/ci.yml`): `npm test`, `build-seo --check`, sitemap/sync/ix-manifest/build-api up to date, preloads, `build-site --check` (only sees committed files). Run them all before pushing. Audit scripts rewrite `docs/QA-SCORES.md` and `docs/qa/*`; commit those or leave them.
