Integer Factorisation

Trial division for small n; Fermat's method when factors are close; the number field sieve is the best classical method; Shor's algorithm threatens RSA.

Mathematics · Number Theory and Cryptography · about 2 minutes

What you'll be able to do

  • Factorise numbers using trial division and Fermat's method
  • Explain how hard factorisation is and how records have progressed

Simple methods

  • Trial division: try primes up to √n; fine for small numbers.
  • Fermat's method: fast when the two factors are close together.
  • So RSA primes must not be too close.

Hardness

  • The best classical algorithm, the general number field sieve, is sub-exponential.
  • Records: RSA-250 (829 bits) was factorised in 2020 using thousands of core-years.
  • 2,048-bit moduli are far out of reach of classical methods.

The quantum threat

  • Shor's algorithm (1994) factorises in polynomial time on a large fault-tolerant quantum computer.
  • Current quantum computers are far too small, but the threat drives post-quantum cryptography.
Worked example

Factorise 5,959 by Fermat's method.

  1. √5,959 ≈ 77.2: try a = 78 (6,084 − 5,959 = 125, not square), a = 79 (282, not square)
  2. a = 80: 6,400 − 5,959 = 441 = 212
  3. 5,959 = (80 − 21)(80 + 21) = 59 × 101

Investigate with the lab. Factorise a few large numbers below 200 and notice you never need to test a divisor above √n, the same reason the sieve can stop at 13.

Common mistakeChoosing RSA primes that are very close together, which Fermat's method exploits.

In 2 lines: Factorising is believed hard classically. That hardness protects RSA.

Practice questions

Answer each one in your head before you open it: recalling beats rereading.

  1. Why must RSA's primes p and q not be too close together?
    • They must be equal
    • n would turn out to be prime, so it couldn't be used
    • Encryption would fail
    • Fermat's method would factorise n quickly
    • It makes no difference
    Show the answer

    Answer: Fermat's method would factorise n quickly. If p ≈ q, then n is close to a square and a − b is small.

  2. What would a large quantum computer running Shor's algorithm do to RSA?
    • Make it twice as secure
    • Nothing
    • Only slow it down
    • Replace primes with squares
    • Factorise n efficiently, breaking it
    Show the answer

    Answer: Factorise n efficiently, breaking it. Shor's algorithm factorises in polynomial time.

  3. Why does trial division only need to test primes up to √n?
    • If n = ab with both factors above √n, then ab > n, so some factor is at most √n
    • Primes above √n don't exist
    • Larger primes always divide n
    • The sieve can't reach beyond √n
    • Testing beyond √n gives wrong answers
    Show the answer

    Answer: If n = ab with both factors above √n, then ab > n, so some factor is at most √n. A composite n always has a prime factor no bigger than √n, so finding none up to √n proves n prime.

Key terms

Fermat's factorisation method
Write n = a2 − b2 = (a − b)(a + b), searching for a from ⌈√n⌉ upwards
Semiprime
A product of two primes, the form of an RSA modulus
