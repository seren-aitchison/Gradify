Computer Science: common exam mistakes

These are the mistakes our Computer Science lessons warn about most, grouped by topic. Read each trap, then cover it and explain the right idea from memory.

Computational Thinking and Problem Solving

  • Treating computer science as "learning to use software" or "learning a language". Languages change every decade; algorithms, data structures and the principles of systems last. From “What is computer science?”
  • Thinking abstraction means "make it vague". An abstraction must be precise about what it keeps; it only removes what doesn't affect the answer. From “Abstraction”
  • Decomposing by when things happen ("first half of the program, second half") rather than by what each part does. Good parts have a single purpose and few connections to other parts. From “Decomposition”
  • Testing an algorithm on one typical example and assuming it is correct. Try edge cases: the first item being largest, all items equal, negative numbers, an empty input. From “Algorithmic thinking”

Python Programming Fundamentals

  • Mixing tabs and spaces, or indenting a line that shouldn't be indented. Python reports an IndentationError; use four spaces per level, as PEP 8 recommends. From “Programs and the Python interpreter”
  • Reading x = x + 1 as a false equation. In programming it is an instruction: "make x one bigger". From “Variables and assignment”
  • Storing a telephone number as an integer. It loses a leading zero and you never do arithmetic on it, so it should be a string. From “Data types and casting”
  • Writing input("Age? ") + 1. The input is a string, so Python raises a TypeError; cast with int() first. From “Input and output”

Data Structures, Files and Robust Code in Python

  • Writing for n in nums: n = n * 2 and expecting the list to change. n is a separate name for each item; reassigning it doesn't alter the list. From “Lists”
  • Writing lst = lst.sort(). sort returns None, so the list is lost; write lst.sort() or lst = sorted(lst). From “List operations and methods”
  • Swapping the indexes. grid[c][r] reads the wrong cell or raises an IndexError when the grid isn't square. From “Two-dimensional lists”
  • Thinking a tuple holding a list is fully frozen. In t = ([1, 2], 3), t[0].append(4) works, because the list inside is still mutable. From “Tuples”

Algorithms

  • Returning "not found" inside the loop on the first mismatch. The return -1 must come after the loop, once every item has been checked. From “Linear search”
  • Forgetting to move low to mid + 1 (or high to mid − 1). Setting low = mid can loop forever when two items remain. From “Binary search”
  • Stopping after one pass. One pass only guarantees the largest item is in place; keep passing until a pass makes no swaps. From “Bubble sort”
  • Confusing insertion sort with bubble sort. Insertion sort moves one item into a growing sorted section; bubble sort swaps neighbours across the whole unsorted part. From “Insertion sort”

Data Structures

  • Treating "stack" and "array" as the same kind of thing. A stack is an ADT; an array is one data structure that can implement it. From “Abstract data types”
  • Assuming Python lists are arrays of values. A list holds references to objects anywhere in memory, which is why it can mix types and grow, at some cost in memory. From “Arrays and records”
  • Forgetting to check for underflow before popping. Popping an empty stack must be handled, or the program reads invalid data or crashes. From “Stacks”
  • Using list.pop(0) for a large queue in Python. Each dequeue shifts every remaining item; use collections.deque instead. From “Queues”

Data Representation

  • Thinking 8 bits can store 256 as the largest number. 28 = 256 is the number of different values; because one of them is 0, the largest is 255. From “Binary and denary”
  • Converting hex to binary via denary for long numbers. Each hex digit maps directly to four bits; the detour through denary is slower and error-prone. From “Hexadecimal”
  • Ignoring the final carry in an exam answer. If the carry goes beyond the available bits, say an overflow has occurred and give the truncated result. From “Binary arithmetic and overflow”
  • Forgetting that a right shift loses the bits that fall off the end. 7 shifted right by 1 is 3, not 3.5. From “Binary shifts”
